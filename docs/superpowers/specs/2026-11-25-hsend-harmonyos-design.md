# HSend 首版设计

## 目标

在本仓库从零建立 HarmonyOS 原生应用 HSend。使用 ArkTS 编写发现、传输和会话逻辑，使用 ArkUI 构建界面。Pura X Max 能在同一局域网内与官方 LocalSend 相互发现，并通过 HTTPS 双向收发文件。内外屏均可完成发送和接收，开合期间保留当前操作和传输状态。

以 LocalSend v2.2 的发现和 Upload API 为协议依据，以官方 LocalSend v1.19.0 Windows 版为首个互通基线。验收时记录双方版本、设备系统版本和网络环境。[LocalSend 协议](https://github.com/localsend/protocol) · [官方客户端 v1.19.0](https://github.com/localsend/localsend/releases/tag/v1.19.0)

首版覆盖 IPv4 局域网、手动确认接收、单文件和多文件、进度、拒绝、取消与失败提示。双方使用 HTTPS，互通基线采用关闭接收 PIN 的官方客户端。浏览器分享、文本和文件夹发送、接收 PIN、协议 v1、仅 IPv6 网络、手动地址发现和系统后台持续接收留待后续扩展。

## 实施方式

- **双向传输闭环，已选择。** 先用最小界面连通发现、系统选文件、接收确认和单文件 HTTPS 双向传输。尽早在目标机型和官方客户端上验证组播、证书和传输。再补多文件、取消和完整的切屏验收。
- **协议模块先行。** 先用独立测试工具验证协议，再接入 ArkUI 和系统文件选择器。便于定位协议问题，完整的真机交互和开合问题会更晚暴露。

## 协议与平台

- **设备发现。** 使用 IPv4 组播 `224.0.0.167:53317` 和 HTTPS 端口 `53317`。启动监听后发公告，并提供手动刷新。依照规范使用 `/api/localsend/v2/register` 回复公告，兼容规范定义的 UDP 回复。按指纹过滤本机和去重，从数据包取得对端地址，使用对端公告的端口。
- **设备身份。** 为每个安装实例生成并在应用私有存储内保存证书及私钥。HTTPS 指纹采用证书 DER 的 SHA-256，按官方客户端的格式发送。连接两端都要能提供各自证书。发送文件或元数据前，在当前连接上确认对端证书匹配已发现设备的指纹。接收方从 TLS 对端证书取得身份并核对声明。组播只用于找到设备，用户确认仍是每次接收的授权步骤。[LocalSend v1.19.0 的 TLS 与发现实现说明](https://github.com/localsend/localsend/blob/v1.19.0/AGENTS.md#networking-rust)
- **传输请求。** 发送方以 `POST /api/localsend/v2/prepare-upload` 提交设备和文件元数据。接收方展示设备名、文件清单和大小。用户接受后返回会话 ID 与每个获准文件的令牌，拒绝或接收端忙时使用协议状态码。首版接收方确认整批文件，发送方按对端实际返回的文件令牌处理部分接受。
- **文件上传。** 对每个获准文件调用 `POST /api/localsend/v2/upload`，使用协议规定的会话 ID、文件 ID 和文件令牌，正文为原始文件字节。HSend 发送时逐个上传，接收时允许同一会话的多个文件并行上传。接收方校验会话绑定的对端、文件令牌和接收字节数。元数据提供 SHA-256 时校验内容，校验不符时返回 `422`。
- **取消与恢复。** 发送方在获得会话 ID 后通过 `POST /api/localsend/v2/cancel` 通知对端，并停止本地上传。接收方主动取消时关闭会话与活动连接，使发送方收到失败。取消、断连与超时都释放资源、清理未完成文件，并允许后续重新发起会话。已成功保存的文件保留。接收端同一时间支持一个待确认或活动会话，对另一会话按规范返回忙状态。

首个技术验收使用 HarmonyOS Network Kit 组播和 TLS Socket，验证双方均能展示自身证书、获取对端证书，并按指纹完成官方 v1.19.0 所需的身份校验。文件和元数据仅在对端身份校验通过后发送。HarmonyOS 的 TLS 服务端处理连接，HTTP/1.1 路由和消息由 ArkTS 处理。若 SDK 的 TLS 接口无法满足这组要求，先记录具体 API 限制和真机结果，再评审传输层选择。HTTPS 仍为首版验收要求。[华为 Socket 开发指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V14/socket-connection-V14/)

本机已发现 DevEco Studio 和 HarmonyOS 26.0.0 SDK。实施时记录构建使用的 SDK、Hvigor 版本和目标真机系统版本，以可编译 HAP 和目标机型可安装为准确定构建及兼容版本。

## 文件与会话

发送文件通过系统文档选择器获取，网络和文件读写按块进行，内存占用随传输块大小和并行数变化。接收文件先写入应用私有目录中的临时文件，校验完成后以安全文件名保存。文件名按单个名称处理并去除路径成分，同名文件保留两份。接收完成后显示文件清单并保留本地接收记录。用户可以从完成页或接收记录使用系统文件选择器导出文件，包括重启后尚未导出的文件。

应用级会话对象管理发现结果、已选文件、目标设备、接收确认、传输计数和最终结果。视图读取会话并提交用户操作。只有应用或网络生命周期可以启动和关闭监听，页面重排不会重建监听或重发请求。网络错误和保存错误在当前会话中呈现，方便用户重新选择或发起传输。

## 主页、Pura X Max 与主题

主页按用户指定的本地 LocalSend 仓库重写。布局基准为提交 `44f48f18` 中的 `app/lib/pages/home_page.dart`、`app/lib/pages/tabs/` 和 `app/lib/widget/responsive_builder.dart`。接收、发送、设置三个标签保持原顺序，默认打开接收。接收页居中显示系统接收图标、设备别名和设备识别号，右上提供连接信息与接收记录入口。发送页先显示文件选择区，再显示附近设备列表，点击设备发起传输。设置页沿用分组列表，首版放置外观与设备名称。

组件图标直接引用 HarmonyOS 标准资源，由 ArkUI 的 `SymbolGlyph` 配合 `$r('sys.symbol.…')` 渲染。接收、发送、设置标签分别使用 `wifi`、`paperplane`、`gearshape`，接收页中央使用 `square_and_arrow_down`。历史、信息、刷新、添加分别使用 `clock`、`info_circle`、`arrow_clockwise`、`plus`。图标颜色取自主题，图标按钮提供中文无障碍名称。浏览器草图使用本地 SDK 预览字体模拟这些资源，原生应用由系统加载。

- **外屏。** 窄窗口沿用 LocalSend 的底部导航，当前标签占据主内容区。接收确认与进度沿用具体会话的独立页面，列表可滚动，主要操作始终可达。
- **内屏。** 宽窗口沿用 LocalSend 的左侧导航，右侧呈现当前标签或会话。使用 ArkUI 可用窗口宽度选择导航样式，以 LocalSend 的 700 和 800 布局断点为起点，并按 Pura X Max 的安全区和旋转行为实测。内容栏采用 LocalSend 的居中限宽结构。
- **开合连续性。** 在外屏和内屏之间切换时保留当前标签、已选文件、目标设备、同一个确认请求、文件进度和已完成文件。布局变更过程中继续使用同一传输会话。
- **配色。** 延续 LocalSend 的浅色和深色结构，应用默认跟随系统主题，设置中可选择浅色或深色。浅色背景使用白色 `#FFFFFF`，深色背景使用黑色 `#000000`。按钮、选中状态和进度使用靛蓝系强调色，浅色候选 `#4343CA`，深色候选 `#A3A6FF`。绿色不用于主题。配合文字和边框区分状态。

华为适配指南给出的典型窗口为外屏竖向约 459 × 672 vp，内屏横向约 939 × 664 vp。应用使用实际窗口尺寸计算布局。[华为阔折叠适配指南](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-purax-guide/)

## 验收

| 场景 | 通过条件 |
| --- | --- |
| 发现与握手 | Pura X Max 与 Windows 官方客户端在同一 Wi-Fi 下能看到彼此。刷新后无重复设备。双方 HTTPS 握手通过，错误指纹连接被拒绝且无文件数据发出 |
| 双向传输 | HSend 与官方客户端分别作为发送、接收方传单文件和多文件。接收文件与原件的 SHA-256 相同，覆盖中文文件名、空文件和大文件 |
| 拒绝与异常 | 验证拒绝、发送方取消、接收方取消、断网、接收端忙。未完成文件被清除，后续请求可重新发起 |
| 文件导出 | 接收后的文件可从完成页导出。重启 HSend 后可从接收记录找到并导出相同文件 |
| 折叠连续性 | 在待发送、待确认、传输中分别执行合上和展开，校验当前标签、选择和待确认请求保留、当前传输继续，并核对最终文件哈希 |
| 主页与主题 | 默认接收页，三项导航顺序与 LocalSend 一致，内外屏分别使用左侧与底部导航。浅色和深色背景、强调色和文本符合设计。长文件名和系统安全区下，发送、接收、拒绝与取消仍可操作 |

本阶段的实现细节由实施者确定，包括模块目录、窗口宽度断点、文件块大小、并行限制及会话超时值。实现者以官方客户端互通和 Pura X Max 真机行为为依据选择默认值，并记录验证方式。
